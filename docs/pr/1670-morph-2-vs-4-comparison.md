# Morph PPT 2.0 vs 4.0 对比与迁移建议

## 改动中心（最近更新）

> 更新时间：2026-03-28

本次对比核心结论：

1. 4.0 保留了 2.0 的“组件优先 + 远端优先 + fallback 不阻塞”主流程。
2. 4.0 把组件使用方式从“可执行实现倾向”收敛为“描述借鉴（non-clone）”。
3. 4.0 强化了视觉可读性：新增密度规则、字号地板、timeline 降级策略。
4. 4.0 的目标不是更花，而是更贴题、更稳定、模板味更低。

---

## 速览（2 vs 4）

### 1) 流程骨架

- 2.0：ModeGate -> StyleGate -> RemoteComponentGate -> Build -> Verify
- 4.0：同骨架保留，重点升级“组件借鉴策略”和“视觉质检规则”

### 2) 组件策略

- 2.0：组件优先，但仍可能被脚本/样例牵引
- 4.0：描述借鉴优先（语义与层级），默认非复刻
  - 每页最多 1 个主借鉴技法
  - 其余区域自由拼装
  - Borrow-not-clone 检查

### 3) 模板策略

- 2.0：模板可参与校准，部分场景更容易变“模板驱动”
- 4.0：模板仍可校准，但默认次级；不鼓励脚本级模板复刻

### 4) 远端抓取

- 2.0：远端优先，失败走本地 snapshot / 内置规则
- 4.0：同样远端优先，但更强调只取描述参考，不直接复刻实现

### 5) 配色策略

- 2.0：强调风格一致，但执行上可能受样例色牵引
- 4.0：明确“借鉴色彩逻辑，不照搬色值”
  - base/accent/emphasis 三色系统
  - 组件必须重着色再入页

### 6) 字号与可读性

- 2.0：有可读性要求，但字号下限不够硬
- 4.0：新增 typography floor
  - body `>=16`
  - `<=14` 仅标签/注释
  - 暗底正文自动 `+1~2pt`

### 7) 空壳大容器问题

- 2.0：容易出现“大容器小内容”
- 4.0：新增密度规则
  - 灵活判断：优先缩卡/合并
  - 硬兜底：`container_height > 2.2x content_height` 触发一次重排

### 8) timeline 稳定性

- 2.0：timeline 使用不稳时容易显得奇怪
- 4.0：新增 timeline 降级规则
  - 条件不足时自动改为 `pillars/evidence/comparison`

### 9) 效果倾向

- 2.0：工程可用、稳定，但有时模板味偏重
- 4.0：原创度更高、主题贴合更好，可读性更稳

### 10) 使用建议

- 默认用 4.0 跑新案例。
- 保留 2.0 作为回退基线（出现异常时用于 A/B 对照）。

---

## 关键差异（展开）

### A. 2.0 的强项

- 远端抓取链路与 fallback 机制成熟。
- 组件优先思路明确，能避免纯自由发挥导致失控。
- Morph 核心约束（命名、ghost、transition、校验）执行稳定。

### B. 2.0 的常见痛点

- 偶发“组件不贴题”或“组件选择过新奇”。
- 容器和内容密度不匹配，产生空壳感。
- 暗底场景下小字号可读性不足。

### C. 4.0 的升级点

- 从“拿实现”转为“借语义与层级”。
- 页面形式更丰富（减少 timeline 依赖）。
- 可读性规则更硬（字号 + 密度 + 反复刻）。

---

## 迁移建议（从 2.0 到 4.0）

1. 生产默认切到 4.0，观察 1 周样本。
2. 保留 2.0 做回退，遇到异常做同题 A/B。
3. 重点观察 3 个指标：
- 是否仍出现“模板复刻感”
- 是否仍出现“大容器小内容”
- 是否仍出现“暗底小字难读”
4. 若三项都明显下降，可将 4.0 固化为默认 Morph 助手。
