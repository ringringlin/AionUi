# Morph PPT 1.0 vs 4.0 对比与优化建议

## 改动中心（最近更新）

> 更新时间：2026-03-28

本轮围绕“减少模板感 + 提升可读性 + 保留创意空间”做了这些关键调整：

1. 组件策略从“可执行实现导向”进一步收敛为“描述借鉴导向”
- 默认只参考 `COMPONENT_LIBRARY.md` 的语义与层级，不走脚本复刻。
- 明确 Borrow-not-clone（借鉴不复刻）检查。

2. 页型能力扩充（解决 timeline 经常怪的问题）
- 在 `pptx-design.md` 增加了 8 个实用页型变体（如 `dual-evidence`、`problem-solution`、`quote-evidence` 等）。
- 增加 `timeline` 降级规则：步骤信息不足时自动优先改 `pillars/evidence/comparison`。

3. 新增“密度灵活判断 + 硬兜底”
- 先走灵活策略：低密度内容自动缩卡/合并卡片。
- 明显失衡才触发硬兜底重排：`container_height > 2.2x content_height`。

4. 新增字号地板（修复“暗底小字看不见”）
- body 默认 `>=16`，`<=14` 仅允许短标签/注释。
- 暗背景 + muted 文本自动 `+1~2pt`。
- 质检新增 typography floor 检查。

5. 设计方向不变
- 继续保留 1.0 的 Morph 硬规则（`!!` / `#sN` / ghost / transition / validate）。
- 4.0 不追求“更花”，而是追求“更贴题、更清楚、更不像模板复刻”。

## 速览（1 vs 4）

### 1) 设计基线

- 1.0：Morph 机制强约束，稳定优先
- 4.0：继承 1.0 基线，再加“非复刻”与主题贴合约束

### 2) 组件策略

- 1.0：组件/样式参考偏“可执行实现”导向
- 4.0：组件借鉴偏“语义结构”导向
  - 每页最多 1 个主借鉴技法
  - 其余区域自由拼装
  - 增加 Borrow-not-clone 检查

### 3) 模板使用

- 1.0：可读模板脚本，容易被样例牵引
- 4.0：模板仅校准，默认不读 `build.sh`（除非明确要求）

### 4) 组件来源读取

- 1.0：可读 `COMPONENT_LIBRARY.md` + 可选 `components.py`
- 4.0：默认只读 `COMPONENT_LIBRARY.md`（描述优先）

### 5) 配色策略

- 1.0：更容易沿用示例色感
- 4.0：只借鉴色彩逻辑，不照搬色值
  - base/accent/emphasis
  - 组件先重着色再落版

### 6) 布局风格风险

- 1.0：模板化风险高
- 4.0：复刻风险降低，但需要防“空壳大容器”

### 7) 密度控制

- 1.0：缺“容器-内容密度”约束
- 4.0：新增“灵活判断 + 硬兜底”
  - 先缩卡/合并卡
  - 明显失衡时强制重排（`container_height > 2.2x content_height`）

### 8) 字体字号

- 1.0：有字体层级，但实战下限偏松
- 4.0：新增字号地板
  - body `>=16`
  - `<=14` 仅短标签可用
  - 暗底正文自动 `+1~2pt`

### 9) 质量门

- 1.0：技术质检强（transition/ghost/validate）
- 4.0：技术门保留 + 视觉门增强（密度、字号、非复刻）

### 10) 最终效果倾向

- 1.0：更稳，但更像模板
- 4.0：更原创、更贴主题，但要靠规则持续收敛质量

## 背景

目标不是推翻 Morph 1.0，而是保留其稳定性，同时降低模板化、提升主题贴合与视觉一致性。

4.0 的核心定位：

- 继承 1.0 的 Morph 硬约束与质检纪律
- 引入“组件描述借鉴、非脚本复刻”的设计策略
- 强化主题语义匹配与配色逻辑一致性

---

## 一、1.0 与 4.0 核心差异

### 1) 设计哲学

- 1.0：稳定优先，流程明确，示例驱动强，易复用固定构图
- 4.0：稳定 + 原创平衡，借鉴组件“逻辑”，避免几何级复刻

### 2) 远端参考使用方式

- 1.0：
  - 可抓组件与模板
  - 可读脚本型参考（`components.py`、模板 `build.sh`）
  - 风险：容易形成“看起来像样例”的结果
- 4.0：
  - 默认组件描述优先（`COMPONENT_LIBRARY.md`）
  - 默认不读 `components.py` / 模板 `build.sh`
  - 强调“借鉴用途、层级、语气”，不照抄坐标与尺寸

### 3) 组件策略

- 1.0：组件/样式参考偏“可执行实现”导向
- 4.0：组件借鉴偏“语义结构”导向
  - 每页最多 1 个主借鉴技法
  - 其余区域自由拼装
  - 增加 Borrow-not-clone 检查

### 4) 配色策略

- 1.0：更依赖示例风格与执行稳定
- 4.0：强调主题配色逻辑
  - base / accent / emphasis 三色系统
  - 组件先重着色再落版
  - 不保留组件默认皮肤色

### 5) 质量风险侧重点

- 1.0：技术质量高（Morph 机制、ghost、transition、校验）
- 4.0：在保留技术质量基础上，额外防止：
  - demo 文案残留
  - 结构抄样例
  - 颜色逻辑不统一

---

## 二、为什么 1.0 成功但容易模板化

### 成功原因

- Morph 机制规则强约束（命名、ghost、transition）
- helper 与校验链条完整
- 生成流程明确，出错时可定位

### 模板化原因

- 示例构建模式影响较强，模型倾向沿用相似构图
- 脚本型远端参考会放大“实现复刻”倾向
- “不要照抄”是软约束，缺少强制反复刻门槛

---

## 三、4.0 当前能力评估

### 已改进点

- 明确“描述借鉴优先，脚本复刻非默认”
- 强化语义匹配与可读性门槛
- 增加“组件重着色”规则
- 增加“借鉴不复刻”检查

### 仍可能出现的问题

- 语义借鉴仍可能被模型过度发挥，导致结构松散
- 某些主题下配色关系虽统一，但层级对比不够
- 复杂主题时组件选择可能偏“新奇”而非“信息有效”

## 四、4.0 优化建议（按优先级）

## P0（建议立即落地）

### 1) 增加“页面意图 -> 组件候选”白名单映射

- 示例：
  - hero -> [弱锚点、主标题强化、背景节奏]
  - evidence -> [数据卡、对比块、指标层]
  - transition -> [低负担过渡元素]
- 作用：减少“莫名其妙组件”被选入

### 2) 增加“组件借鉴理由”一行证据

- 每页输出：`anchor_reason=<why this component fits intent>`
- 作用：便于快速判断是否语义匹配，不靠肉眼猜

### 3) 配色层级检查前置

- 在 build 前做一次简单预检：
  - 背景层、装饰层、内容层是否符合强弱关系
  - 文字对比是否足够
- 作用：减少后期返工

## P1（建议短期落地）

### 4) 建立“反复刻阈值”

- 当与单一样例在结构顺序、间距节奏、视觉重心三项中重合 >=2 时，强制重排
- 作用：把“非复刻”从描述规则变成可执行规则

### 5) 增加“轻装饰默认档”

- 默认 `L2 <= 1`，`L4 = 0`
- 只有在可读性稳定后再升装饰
- 作用：先稳后美，避免花哨覆盖内容

## P2（中期迭代）

### 6) 组件借鉴知识卡片化

- 将 COMPONENT_LIBRARY.md 抽为结构化卡片：
  - `适用场景` / `信息层级` / `视觉语气` / `禁用场景`
- 作用：降低模型误读描述的概率

### 7) 引入简单审美一致性打分

- 维度：层级清晰、留白节奏、色彩一致、动线连贯
- 低于阈值时，优先触发降复杂策略

---

## 五、建议的稳定落地策略

推荐策略：

- 生产默认使用 4.0
- 保留 1.0 作为“稳定回退基线”
- 对外话术强调“借鉴逻辑，不复刻样例”

这样可以兼顾：

- 1.0 的稳定执行力
- 4.0 的风格原创性与主题贴合度

---

## 六、验收建议（快速）

用同一主题连续跑 3 次，检查三项：

1. 是否出现样例化重构图
2. 是否有 demo/教程文案残留
3. 是否配色逻辑一致且可读性稳定

若三次都通过，说明 4.0 基本可作为默认方案。
